# 本地网页与公网网页维护边界

本文件用于避免后续优化时混淆两套用户端。

## 产品约束

本地网页和公网网页应保持相同的核心交互：

- 默认只加载当前对话最近 6 轮。
- 支持“查看更早 6 轮”和“查看全部”。
- 快速切换时取消旧请求，以最后一次点击为准。
- 支持输入、附件、新建对话、模型与推理强度选择。
- 同一对话运行中，后到消息作为补充引导。

这些属于双端共同功能。任何一端修改以上行为，都必须检查另一端。

## 主要区别

| 项目 | 本地网页 | 公网网页 |
|---|---|---|
| 入口 | 本机回环地址 127.0.0.1:8765 | 用户配置的 HTTPS 域名 |
| 身份验证 | 仅本机回环访问，自动信任 | 飞书 OAuth，并核对所有者身份 |
| 历史来源 | 本机桥直接读取 Codex 会话 | 云端读取本机桥同步的历史快照 |
| PC 离线 | 无法使用 | 可查看最后一次已同步历史，不能执行新任务 |
| 输入路径 | 浏览器直接交给本机桥 | 云端排队，本机桥主动领取 |
| 文件能力 | 可读取或打开本机文件 | 只能查看临时云端副本、文件位置或同步盘提示 |
| 后端更新 | 修改 app/bridge.py 后需重启本机桥 | 修改 cloud/app.py 后需部署并重启云端服务 |

“最近 6 轮/查看更多/查看全部”在两端界面相同，但底层实现不同：

- 本地端由 app/bridge.py 从 Codex 读取后裁剪返回。
- 公网端默认只同步最近7天更新过的对话最近6轮。运行中的对话始终活跃，网页打开后临时关注30分钟；只有查看中的对话持续快速检查。
- 公网端通过 cloud/history_store.py 请求更早窗口或完整历史，最新快照与历史窗口分别缓存；不会每次后台上传完整历史。
- 本机当前 thread/read 接口仍返回完整历史，app/history_sync.py 在本机裁剪后传输。历史按需请求不发送给模型，不产生新回合。
- 对话列表只同步元数据；历史加载进度、错误和内容同步时间显示在当前对话标题下。
- 两端浏览器分别使用 web/app.js 和 cloud/web/app.js，切换取消逻辑必须同步维护。

## 修改检查清单

涉及对话显示、切换、轮询、输入、附件、模型或状态时：

1. 同时检查 web/ 与 cloud/web/。
2. 同时检查 app/bridge.py 与 cloud/app.py 的对应接口。
3. 验证首次为 6 轮、逐批增加 6 轮、查看全部。
4. 验证快速点击多个对话时，最后点击的对话最终显示。
5. 验证本地访问不触发飞书 OAuth，公网访问仍要求飞书 OAuth。
6. 后端有变化时，分别说明本机桥是否需要手动重启、云端是否已经部署。
7. 发布公开版前执行隐私扫描，不带入域名、IP、密钥、会话或运行数据。
